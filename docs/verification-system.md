# Verification system

Verification answers:

> **What is this organization or account authorized to represent inside Go Native?**

It does not determine whether a person is Indigenous.

## Organization verification states

- Unverified
- Verification Pending
- Verified
- Needs Review
- Suspended

## Possible verification evidence

Depending on organization type, verification may use:

- domain/email control
- legal/public registry evidence
- official organization website
- designated representative confirmation
- direct program-owner confirmation
- Nation/community-specific attestation where appropriate
- school/funder/government directory records

Verification requirements should be conditional by organization type.

## Badges

A verification badge should expose:

- scope of verification
- verifier/review source
- verification date
- last reviewed date
- expiry/review date if applicable

A badge must never imply that Go Native verified a person's Indigenous identity.

## Permissions

Verification and authorization are separate.

A verified organization still requires correct workspace membership and role permissions before a member can publish, edit, message, review applications, or view analytics.

## Lifecycle

Support:

Verify → Publish → Periodic Review → Correction / Appeal → Suspension / Reverification

Changes to verification state create audit events.
